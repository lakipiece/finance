입력부 — D안에서 가장 큰 쟁점

현행 인풋은 border-bottom:1px solid #e2e8f0 밑줄형이다. D안(=B)의 테두리 0 원칙과 정면으로 충돌한다. 밑줄을 남기면 원칙이 깨지고, 지우면 입력 필드인지 알 수 없다. → 채움형(filled) 인풋으로 전환하는 것이 D안의 유일한 정합 해법이다. 아래는 그 결과.

항목변화 / 판단
인풋 형태※ 핵심 결정 밑줄형 → 채움형 전환. 채움색은 표면 토큰(#f1f3f7, 청색기)이 아니라 중성 필드 토큰 #f1f3f7을 신설해 쓴다 — 폼은 필드가 많아 청색 틴트가 누적되면 화면이 하늘색으로 물든다. field.input 전면 치환이라 27개 화면 전부 영향. D안을 고르면 이건 선택이 아니라 필수 — 밑줄을 남기면 "테두리 0"이 거짓이 된다
포커스 규칙현행은 밑줄 브랜드색 / 검색창만 focus:ring — 두 벌. D안은 배경이 흰색으로 올라오고 잉크 링 2px 한 벌로 통일. 표면 레이어링과 같은 논리라 설명이 쉬움
금액 필드20px·700·tabular로 단독 확대하고 우측 정렬 + 단위 분리. 아래 +1천/+1만/+10만/00 퀵 칩 — 가계부 입력은 금액이 전체 시간의 대부분
분류 선택드롭다운 대신 pill 4개 상시 노출 (선택=솔리드, 미선택=10% 틴트). 4대 분류가 고정이라 접을 이유가 없고, 배지 시스템을 그대로 재사용하므로 신규 토큰 0
밀도 예외입력 화면은 C 밀도를 적용하지 않는다. 필드 간격 14px·라운딩 11px·11px 국문 라벨 = B안 그대로. 밀도 압축은 표·리스트 전용
연속 입력"저장 후 계속 입력" 토글 상시 ON 기본. 저장 시 모달 유지·금액만 비우고 포커스 복귀. 현행엔 없는 동작 — 기능 추가 필요
입금모달을 아예 쓰지 않고 표 인라인 입력 행. 반복 입력 특성상 모달 열기/닫기 왕복이 가장 큰 비용. modal.*과 별개의 신규 패턴 — 작업량 있음
모달 오버레이사용 0회인 glass.overlay(#0d1c2e/30 + blur(6px))의 값을 정본으로 승격하고, modal.overlay·modal.overlayTop이 그 값을 쓰도록 교체(z-index 차이는 유지). bg-black/40은 폐기
날짜 입력DateInput.tsx·YearMonthPicker.tsx가 field.*를 안 쓰는 문제는 D안에서도 그대로 남는다. 채움형 전환에 맞춰 같이 손대야 함
키보드⏎ 저장, Esc 취소, Tab 순서 = 금액 → 분류 → 내역. 현행 미정의 — 명세 필요
모바일채움형 + B안 여백이라 터치 타깃 44px를 여유 있게 넘긴다(밑줄형 미달 해결). 금액 퀵 칩은 숫자 키패드 위 고정 바로 승격 권장
